======================================================================
        cnAgentOS — 功能需求与 AI 提示词设计文档
======================================================================

本文档记录了项目中各功能模块的开发需求与 AI 分析提示词设计，
便于团队协作与后续维护迭代。

======================================================================
一、智能聊天子系统（IM）开发需求
======================================================================

【1.1 通讯录交互增强】
----------------------------------------------------------------------
- 通讯录中的好友支持点击查看详情与发起对话
- 支持删除指定联系人，删除后双方通讯录同步更新


【1.2 消息撤回】
----------------------------------------------------------------------
- 右键点击自己发送的消息弹出上下文菜单，提供「撤回」选项
- 发送后 2 分钟内的消息可撤回，超过 2 分钟的选项置灰不可用
- 撤回后消息内容替换为系统提示（区分自己撤回与对方撤回）
- 私聊和群聊消息均支持撤回


【1.3 群聊创建与管理】
----------------------------------------------------------------------
- 群聊页面提供「创建群聊」按钮
- 弹出通讯录好友多选界面，选中好友后自动生成群名称
  （格式：成员A、成员B、成员C...）
- 创建成功后，群内所有成员收到入群系统消息
- 群创建者自动成为群主


【1.4 退出与解散群聊】
----------------------------------------------------------------------
- 群成员可右键群聊选择「退出群聊」
- 群主可解散群聊（需二次确认）
- 群主退出前必须先将群主身份转让给另一位群成员
- 解散群聊后所有成员自动移除、聊天记录保留备查


【1.5 修改群名称】
----------------------------------------------------------------------
- 群资料页支持编辑群名称
- 群名称行与普通群成员行做视觉区分（带「群名称」标签）
- 修改后群内自动发送系统提示消息
- 侧边栏群列表实时刷新


【1.6 数字员工在聊天系统中的集成】
----------------------------------------------------------------------
- 数字员工以「普通好友 / 群成员」身份出现在通讯录和群聊中
- AI 型数字员工：通过 @别名 触发，调用 AI 大模型进行多轮上下文对话
- API 型数字员工：通过 @别名 触发，调用外部接口返回结构化结果
- 支持多轮上下文感知：检测对话上下文自动延续 @employee 模式
- 数字员工在通讯录中显示特殊标识（图标和颜色区分）
- SSE 流式或结构化消息推送


【1.7 后台管理 - 群管理】
----------------------------------------------------------------------
- 查看所有群列表、基本信息、成员列表
- 解散指定群聊、对群聊进行禁言管控
- 向指定群聊发送系统公告
- 查看群聊历史消息记录（分页浏览，区分系统消息与用户消息）


【1.8 后台管理 - 文件管理】
----------------------------------------------------------------------
- 统一查看和管理所有用户收发的聊天文件
- 文件去重存储，避免重复文件占用空间
- 支持文件预览、删除等管理操作


【1.9 后台管理 - 服务器管理】
----------------------------------------------------------------------
- 配置和管理多台聊天服务器
- 用户使用过程中程序自动在多服务器间切换
- 保障系统高可用与稳定性


【1.10 后台管理 - AI 工具配置】（已合并至数字员工页面）
----------------------------------------------------------------------
- 可视化展示和管理系统中所有 AI 调用的工具集
- 支持将工具绑定到指定的数字员工
- 支持启用和禁用


【1.11 手势识别交互系统】
----------------------------------------------------------------------
- 基于 MediaPipe Hands 实现 5 种手势实时识别：
  张开手掌（OPEN_PALM）、食指（INDEX_UP）、食指+中指（INDEX_MIDDLE_UP）、
  OK手势（OK）、握拳（FIST）
- 手势检测间隔 1 秒防抖，持续保持手势以触发操作
- 关节角度法（MCP→PIP→TIP 三点夹角）判断手指伸展，2D 投影无关
- 指尖聚类法（五指指尖最大半径 < 0.12）检测握拳，拇指位置辅助判定
- 帧率节流（50ms/帧）+ 健康看门狗（8s 无检测自动重启）+ 定时重启（120s）
- 手掌图标按钮（固定右下悬浮），点击启用/关闭手势识别
- 手势与业务操作映射：
  - OPEN_PALM：打开快捷菜单 / 发送消息
  - INDEX_UP：向下翻页 / 滚动
  - INDEX_MIDDLE_UP：向上翻页 / 滚动
  - OK：确认 / 发送消息 / 新建对话
  - FIST：关闭弹窗 / 返回首页


【1.12 AI 语音朗读（TTS）】
----------------------------------------------------------------------
- 使用浏览器内置 Web Speech API（window.speechSynthesis）实现中文 TTS
- 右键文字消息弹出"语音朗读"菜单项，点击后 AI 朗读该条消息
- 输入工具栏提供喇叭图标按钮，输入文字后点击 → TTS 朗读预览 → 自动以 voice 类型发送
- 朗读中的消息气泡显示蓝色高亮边框（speech-highlight），朗读完毕自动消失
- TTS 参数：zh-CN 语言、1.0 语速、0.8 音量
- 语音消息无音频文件时自动走 TTS 播放替代


【1.13 语音消息录制与发送】
----------------------------------------------------------------------
- 麦克风权限弹窗：首次点击麦克风时检查权限，未授权弹出"申请麦克风权限"对话框
- 输入工具栏麦克风图标切换文字/语音输入模式（绿色高亮表示语音模式）
- MediaRecorder API 录制音频（优先 webm，降级 mp4），按住说话，松开发送
- 最长录音 60 秒自动停止，不足 1 秒自动丢弃（防误触）
- 语音消息气泡：喇叭图标（纯 CSS 锥体 + 底座 + 2 道声波弧）+ 时长文字
- 本人发送（绿色喇叭）与对方发送（灰色喇叭）颜色区分，别人消息左右镜像布局
- 未读语音消息红点提示，点击播放后红点消失
- 播放动画：声波弧依次闪烁（spk-wave），同时仅一个语音播放


【1.14 新消息提示音】
----------------------------------------------------------------------
- Web Audio API 纯前端生成"叮-咚"双音阶短铃（正弦波、280ms、gain 0.25）
- 触发场景：
  - pollPrivate() — 接收到他人私聊消息时（m.from_user_id !== userId，非撤回）
  - pollGroup() — 接收到他人群聊消息或群聊邀请系统消息时
  - updateReqBadge() — 好友请求数较上次轮询增加时（d.count > _lastReqCount）
- 防误报：初次加载不触发，撤回消息不触发，AudioContext 用完自动 close()

二、智慧舆情分析 — AI 分析提示词
======================================================================

以下提示词用于 SSE 流式 AI 分析接口（SentimentAIAnalyzeHandler），
AI 模型接收系统数据上下文 + 分析指令，流式输出 Markdown 报告。

【2.1 系统上下文 Prompt（各分析类型共用）】
----------------------------------------------------------------------
你是一个专业的智慧舆情分析系统。请根据以下系统数据进行分析。

## 系统数据概览
- 总用户对话数: {user_count}
- 总消息条数: {chat_count}
- IM私聊消息数: {im_count}
- IM群聊消息数: {group_count}
- 瞭望采集数据: {watch_count} 条
- 深度采集数据: {deep_crawl} 条

## 近期对话样本
{chat_samples}

## 近期IM聊天样本
{im_samples}

## 瞭望关键词分布
{watch_info}


【2.2 综合舆情分析】
----------------------------------------------------------------------
## 分析任务
请进行全面综合的舆情分析，包括：
1. 整体态势评估：系统的整体运行情况
2. 热点话题识别：从对话和瞭望数据中识别热点话题
3. 风险指标评估：评估潜在风险点
4. 趋势预测：对未来趋势的判断
5. 建议措施：给出管理建议

请以 Markdown 格式输出，并在末尾以 JSON 标注风险等级和关键词：
```json
{"risk_level": "low|medium|high", "risk_score": 0-100,
 "keywords": ["关键词1","关键词2"], "summary": "一句话总结"}
```


【2.3 对话风险检测】（覆盖私聊 + 群聊 + AI 对话）
----------------------------------------------------------------------
## 分析任务
请针对系统对话数据（含用户对话、IM 私聊、IM 群聊）进行风险分析：
1. 对话主题分布：用户主要在讨论什么
2. 情感倾向：正面 / 负面 / 中性分布
3. 异常行为检测：识别异常对话模式或潜在敏感内容
4. 用户活跃度：参与度评估

请以 Markdown 格式输出，并在末尾以 JSON 标注风险等级和关键词：
```json
{"risk_level": "low|medium|high", "risk_score": 0-100,
 "keywords": ["关键词1","关键词2"], "summary": "一句话总结"}
```


【2.4 瞭望趋势洞察】
----------------------------------------------------------------------
## 分析任务
请针对瞭望采集数据进行分析：
1. 数据采集概况：采集数据的整体状况
2. 关键词趋势：热门关键词的变化趋势
3. 数据质量评估：采集数据的完整性和质量
4. 信息来源分布：不同来源的数据量分布

请以 Markdown 格式输出，并在末尾以 JSON 标注风险等级和关键词：
```json
{"risk_level": "low|medium|high", "risk_score": 0-100,
 "keywords": ["关键词1","关键词2"], "summary": "一句话总结"}
```


【2.5 风险预警评估】
----------------------------------------------------------------------
## 分析任务
请进行风险预警评估：
1. 风险识别：识别当前存在的风险点
2. 严重程度：评估每个风险的严重程度
3. 影响范围：评估风险的潜在影响范围
4. 应急建议：给出风险应对建议

请以 Markdown 格式输出，并在末尾以 JSON 标注风险等级和关键词：
```json
{"risk_level": "low|medium|high", "risk_score": 0-100,
 "keywords": ["关键词1","关键词2"], "summary": "一句话总结"}
```
【2.6 自动定时爬取功能】
----------------------------------------------------------------------
在瞭望采集模块中实现定时自动爬取，支持三种执行模式：

- **立刻采集**（默认）：不展开定时模块时，点击开始采集立即执行
- **北京时间定时**：选择具体北京时间（如 2026-05-28 22:00:00），到达后自动执行
  - 初始时间为电脑当前时刻
  - 6 个数字输入框：年/月/日/时/分/秒，支持滚动与键盘输入
  - 数字颜色为白色，等宽字体，深色背景
- **倒计时**：设置时/分/秒倒计时（初始 0），计时归零后自动执行
  - 最大定时不超过一年

实现要点：
- 拨动开关（iOS 风格 toggle）切换北京时间/倒计时两种定时方式
- 到达时间后播放"叮"声提示音（Web Audio API 双音阶正弦波）
- 前端实时倒计时显示（HH:MM:SS），归零后自动跳转数据仓库页面
- 后端 tornado.ioloop.call_later() 事件循环调度，单线程无阻塞
- 时间校验：过去时间拒绝、超一年拒绝、倒计时必须 > 0

======================================================================
三、系统架构设计要点
======================================================================

【3.1 数据流设计】
- 聊天消息来源三合一：conversation_messages + im_messages + im_group_messages
- 舆情分析采样策略：每种消息源取最近 15 条作为 AI 上下文
- 词云数据源：私聊 + 群聊 + AI 对话的文本消息分词统计

【3.2 菜单组织原则】
- 最多两级菜单，文件夹（父级）不设 URL
- 功能归类按实际使用场景分组（AI 引擎 / 数据采集 / 智慧舆情 / 智能聊天）
- 工具与宿主合并展示（AI 工具配置集成在数字员工页面）
- 超级管理员可管理「用户权限」和「系统配置」，管理员角色不包含这两项

【3.3 认证体系】
- AdminBaseHandler：后台管理，验证 admin_user Cookie
- BaseHandler：用户侧，验证 username Cookie
- 两套 Cookie 互不干扰
